# 从真实架构图里提炼研究判断：第一轮跨论文对照

## 先给结论（不是统一美术风格）

本轮人工查看了 **3 篇原始会议论文的 9 幅非实验结果图**，包括原 PDF 像素、图注和相邻正文。可核查记录见 [expert-papers.json](expert-papers.json)。样本来自 MIT/NVIDIA、CMU/Intel、Stanford 的不同作者团队；机构只用于交代样本来源，不用于给图打分。这里只报告这个小样本的观察，不能称作整个领域的统计共识，也没有访问作者来验证其意图。

最值得训练的能力是：**选出当前要成立的一个论点，确定读者必须看见什么关系，再决定不画什么。** 不是“框越少越高级”，也不是“统一成某种蓝灰配色”。以下按优先级排列。

### P0：先决定这张图回答哪一个问题，而不是先列全系统组件

- **证据**：Eyeriss 图1解释存储层级，图5解释一个 PE 内的运算序列，图6解释 PE 之间三类数据流；不同问题使用不同图法。RowClone 图1给 DRAM 层次，图4只展开一次复制的状态变化，图5解释跨 bank 路径。
- **判断**：总览、局部机制、时间演进不是必须挤进同一幅图的三个装饰层。读者需要的理解顺序决定拆图位置。
- **初学者式草稿 → 修改**：CPU、软件接口、缓存、NoC、PE 内部、所有时序全画在一张总览里 → 总览只留下定位研究对象的边界与主要连接；把“为什么可行”放到一个局部机制图，另用时间轴解释先后。删掉的细节在正文或后图承接，不是无条件删除。

### P0：做比较时锁定不变量，让差异成为读图任务

- **证据**：Eyeriss 图6三次复用相同的逻辑 PE 网格，分别画 filter、ifmap、psum；RowClone 图5在同一芯片边界内同时标明 TRANSFER 与 READ/WRITE 路径。
- **判断**：比较可以是并排小图，也可以是同底图的有限路径对照；并不总要“baseline 左、新方案右”。关键是读者不用重新解码布局。
- **初学者式草稿 → 修改**：三种流叠在一个网格里交叉，或 baseline/proposal 完全不同布局 → 保留节点坐标、命名和尺度；拆成等尺寸面板，每面板只变论证变量。空间不足时，像 RowClone 图5那样保留共同底图，但给路径明确名称。

### P0：省略是技术声明，不是美化借口

- **证据**：Plasticine 图3图注明说仅显示4级、4条 SIMD lane，省去部分控制信号；图5注明实际组织为16×8。Eyeriss 图5、6给出示例尺寸 R=3、H=5。
- **判断**：示例规模必须和真实规模分开。无法从“画了四个”推断“硬件只有四个”。这种边界声明比增加一层阴影重要得多。
- **初学者式草稿 → 修改**：画满所有重复单元，或随意缩成四个却不解释 → 只保留足以证明重复规律的实例，在图注写清“示意规模/实际规模/未展示哪些连线”。在没有核实前不要写具体真实数量。

### P1：先定义视觉编码的语义，再调视觉参数

- **证据**：RowClone 图1黑白灰的嵌套与放大虚线就能说明 chip→bank→subarray；Eyeriss 图6颜色与数据类型绑定，同时仍有名称和箭头方向；Plasticine 图3、4延续蓝色数据部分、橙色控制部分。
- **判断**：重要的是编码一致、可复述，而非颜色数量越少越好。对层级图，包含和位置很重要；对 Eyeriss 图5，时间顺序更重要。相同颜色未必跨论文同义，不能抽成全领域色表；线宽、颜色若承担数量或角色语义，必须在结构设计时确定，不能等到最后当装饰添加。
- **初学者式草稿 → 修改**：每个框任意不同颜色 → 先用位置/包含关系组织概念，仅对需要区分的角色分色；加可读标签，让信息不只依赖色觉。删除不表达任何区别的颜色。

### P1：细节密度由论点决定，不是固定的“每图最多几块”

- **证据**：Plasticine 图3保留不少寄存器、功能单元与连线，图4也保留 scratchpad 接口，不能算极简；RowClone 图4下钻到字线/位线与单元状态，因为物理机制本身需要这一层；Eyeriss 图1则保持高层。
- **判断**：专业感不是低信息密度。需要保留支持因果解释的细节，删除无助于当前问题的细节。
- **初学者式草稿 → 修改**：为“干净”把决定机制的队列/缓存/控制删掉 → 问“删后还能解释为什么可行、约束在哪里吗？”若不能，恢复该对象，把次要内容移至局部图或注释，而不是强行简化。

## 有用的反例：不能把共性误写成死规矩

1. **“一律黑白”不成立**：RowClone 灰度有效，Eyeriss 与 Plasticine 的功能分色也有效。
2. **“一张图一层抽象”过强**：Eyeriss 图1、RowClone 图1的带关联局部放大很好地桥接层级；应禁止的是无标记混层，不是放大图本身。
3. **“必须从总览开始”不成立**：Plasticine 图3、4先局部，图5再芯片；顺序服务正文论证。
4. **“所有线都不许交叉/必须稀疏”不成立**：真实 datapath 图可以较密；是否能追踪必要路径，比机械删线更重要。
5. **“新东西一定用红色”无证据**：这些样本里 novelty 可以是已有对象间的关系、操作或调度，不必是一个彩色盒子。

## 下一张原创图的修改顺序

1. 写一句读者看图后应能回答的问题；拒绝“展示整个系统”这种无边界目标。
2. 给每个对象和每条边写角色：必要背景、机制证据、上下文、可移出。不能解释用途的先移走。
3. 确定比较不变量；相同对象尽量同名、同位置、同尺度。
4. 选图法与编码语义：结构层级、局部 datapath、时间序列、状态转换、并排对照，不要默认全用方框箭头；同时确定颜色、线型、线宽是否表示角色、关系或数量。
5. 明确示意规模、未显示内容、箭头含义；避免把逻辑图误读成物理结构。
6. 最后精调字体、对齐以及已选编码的具体线宽/色值参数，而不是最后才决定它们的语义；按论文实际栏宽检查，不以大画布截图代替。

**本轮限制**：是有目的的小样本，不是随机采样；年份集中在2013–2017，两个加速器论文、一个存储机制论文，还不足以推断现代 CPU/cache/coherence 图的全部惯例。当前只收注释、链接和图号；原始 PDF 与渲染均留在 `/tmp`，不进入公开仓库。不把作者图重绘成可再分发“模板”。
