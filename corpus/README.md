**当前是 3 篇论文、9 张逐图核验的试点，不是 100 篇调查，也不代表领域频率。**
只纳入结构、流程、机制或表示图；排除实验结果曲线、柱状图、性能表。机制图中存在语义线宽，不自动使它成为实验结果图。

## 如何用于选图和设计

| 读者需要回答的问题 | 本种子中的证据 | 建议选图 |
|---|---|---|
| 研究的对象是什么，具体运行在哪？ | FireSim 图1与图2 | 目标拓扑 + 目标/宿主映射，必要时拆成两图 |
| 整体组件职责是什么？ | Ray 图5、AIFM 图3 | 分层/边界总览 |
| 贡献通过哪条处理路径实现？ | FireSim 图3、Ray 图6 | 带入口出口及控制关系的机制图 |
| 存在几种不能混淆的依赖？ | Ray 图4 | 有明确边类型图例的依赖图 |
| 新表示如何编码状态？ | AIFM 图4 | 同基准的位域对照图 |
| 全局结构怎样落到局部数据？ | AIFM 图5 | 多层组织 + 对象放大图 |

以上是从小样本提炼的**待继续验证的设计启发**，不是“顶会都这样画”的规则。
一篇论文不必把这些图全部画一遍：先写一个读者问题，再判断它能否由已有图无歧义回答。

特别注意：Ray 图6的箭头粗细由图注明确赋予请求率含义；AIFM 图3的填色明确区分数据结构和运行时；AIFM 图5中不同箭头不能一律解读为数据流。美化前必须保留这些语义。

## 数据契约

两个 JSON 均为 `{ "schema_version": "0.1.0", "corpus_status": "pilot_primary_source_checked", "records": [...] }`。

- `papers.json`：`id` 为稳定键；含标题、会议、年份、官方来源、PDF、文件哈希、已检查图号及访问限制。
- `figures.json`：`paper_id` 外键、`figure_number`、`pdf_page_1based` 和 `printed_page` 精确定位；`source_url` 可直接定位原 PDF 页。
- `main_object`、`reader_question`：图解的是何物、服务哪项贡献理解，而非整篇论文泛泛总结。
- `global_organization`：整体排布、分组、层次与重复策略。
- `explicit_semantic_mappings`：图例/图注/正文明确的语义，或图上直接标明的边界和角色。
- `local_style_observations`：直接观察的线、框、色、字体/标签等，不自动赋予机制含义。
- `inferred_design_reading`：标注者对视觉组织作用的解释，不能冒充作者意图。
- `caption_paraphrase_zh`、`relevant_text`：短中文转述与章节定位，不转载长图注。
- `pattern_applicability`、`ambiguities`、`design_lesson`：什么时候借鉴、哪里容易读错、如何转化为自己的图。
- `evidence_status`：该记录是否经过元数据、像素、图注、正文四项检查。

## 边界与可复核性

- 取样优先合法可访问的原论文，并覆盖不同图形职责；不是随机抽样，年代集中于 2018–2020，会议覆盖仅 ISCA/OSDI。未覆盖 MICRO/DAC/HPCA/ASPLOS/ATC/IPDPS，不据此推断会议间差异。
- FireSim 的 IEEE 页面要求 JavaScript 验证；未绕过。采用项目官方出版记录、作者原文 PDF 与会议官网交叉核验，未声称读取 IEEE 页面正文。
- 目前由单次人工/模型辅助标注完成，没有第二标注者一致性测量；样式解释可能有偏差。字段刻意保留歧义，而非强行归类。
- 原 PDF、渲染页图和文本仅保存在研究临时目录，不进入公开仓库。公开的是来源链接、图号与原创分析，不重新分发论文图像；开放获取不等于开放图像许可。
- 后续扩充应记录筛选原因和排除的实验图，逐项复核，而非先凑数量。适合增加：时间推进机制、状态转换、编译流程以及另一篇不同范式模拟器。
