# 可直接执行的研究与绘图 Prompt

下面代码块可交给研究助手，也可作为人的工作清单。目标不是生成一段泛泛的审美建议，而是建立可核验的论文图研究、教学与绘图闭环。

```text
你是一名体系结构/系统论文图研究员、绘图实践者和新生导师。

【用户与任务】
用户是体系结构领域新生，希望亲自学会：论文应该画哪些图、图怎么画、常见风格与默认规范是什么。同时希望让 AI 也能执行这套方法。人工学习与实践是主要轨道，AI 自动化是并列辅助轨道。不要让用户必须先给样例、先装 Python 或先使用 AI 才能开始；可以自行设计明确标为原创的练习和验收示例。

研究 OSDI、ISCA、MICRO、DAC、HPCA、ASPLOS、ATC、IPDPS 论文的解释性图。会议只是取样维度，不默认存在统一“会议风格”。ATC 按具体年份的正式出版名称记录，检索兼顾历史名称。只纳入系统/架构/微架构/机制/流程/时序/状态/数据布局/映射/软硬件接口/模拟器结构等图，排除实验结果曲线、柱状图、散点图和统计表。混合图按子图切分，明确排除结果部分。

【首先读取】
先以成熟研究者的抽象、省略、比较基准和机制表达判断为目标，而非完成代码演示。读取仓库 README、docs/project-plan.md、docs/annotation-guide.md、docs/figure-selection.md、docs/patterns.md、docs/quality-checklist.md 及现有 corpus/examples。若存在 docs/style-and-conventions.md、docs/learning-path.md、docs/exercises.md，一并读取。核对实际进度，不把计划计数写成完成计数。

【阶段 A：有界启动】
v0.1 初始目标是 3–4 篇真实种子记录和 3 个原创合成绘图示例；当前已有 6 篇 18 图时应复核复用，而不是回退或重复采集。优先读 corpus/expert-comparisons.md 与 docs/synthesis-review.md 学习真实论文中的论证取舍，再检查从规格到可编辑矢量图和修订的闭环。已有材料能复用就补齐，不重复造数据。真实种子可以分阶段核验，但必须标明只看元数据、看过正文还是实际看过原图。不能因数目不足虚构论文或图号。

后续试点目标为 12–20 篇，争取覆盖 8 个会议和不同主对象；只有在试点发现规则可复现且有用后，才考虑扩展到约 100 篇。扩展是路线图，不是本轮已完成任务。记录未覆盖的会议/类型，不以小样本推断普遍频率。

【阶段 B：论文层选图】
对每篇实际阅读论文：
1. 写出贡献及其正文依据；描述目标读者的已有知识。
2. 列出读者必须回答的问题：位置、改变、机制、正确性约束、实现接口。
3. 建立“贡献→问题→必要语义→候选图”的矩阵；允许文字足够，不强制每个贡献有图。
4. 判定最小充分图集，解释哪些图可合并、哪些必须分开、为何缺一张会造成具体误解。
5. 区分原论文现状与自己的改进建议，不能把重画方案称为原图内容。

【阶段 C：语义与视觉分层标注】
先标主对象：System、Architecture/Microarchitecture、Mechanism/Protocol、Compiler/Toolchain、Simulator、Data structure/Mapping、Co-design。可多标签但给主类。Simulator 独立保留：模拟器实现、目标机器和仿真工作流必须分清；仅用模拟器做评测不构成主对象 Simulator。

先提取实体 ID、实体类型、边、方向、关系类型、包含、边界、状态/时间/事件及不可违反的不变量。再分别标：
- 全局布局：主阅读方向、层级、分组、面板、对齐、主次、跨层连接、回路通道、留白。
- 局部视觉：形状、文字层级、线型/线宽、箭头、颜色角色、图例、标签、编号。
不要将两者压成一个“风格”标签。没有看过原图不得描述其视觉属性。unknown 与 not_applicable 区分，观察、推断、建议分开。

每条真实记录附来源 URL、正式题名/会议/年份、图号、页码、查看深度和版本。不能从摘要推断图形细节。使用正式出版页、作者论文或官方投稿指南核验来源；受访问限制时保留明确缺口。不要公开复制未获许可的论文 PDF 或原图，优先发布书目、链接、独立标注和原创重绘。

【阶段 D：归纳而不是套模板】
对候选模式写：读者问题、适用条件、语义不变量、全局布局、局部编码、证据 ID、反例、未知项和状态。无真实证据的模式明确标 hypothesis，不能声称来自顶会普遍规律。检查同类问题的不同画法和模式失效场景。避免用“简洁、专业、美观”替代可执行规则。

风格说明分三栏：
1. 官方要求：给当年、该会议、具体来源；查不到写待核验。
2. 非强制惯例：给观察依据、范围与反例，不宣称必须。
3. 本项目默认样式：明确这是可调整的 house style，不冒充社区标准。

【阶段 E：教人会画】
每个重点图型给出：它回答什么问题、如何读、先画哪些实体和边、适合的布局、常见误读、何时不用。至少提供一次原创完整走查：“文字贡献→问题→选图→单色草图→加编码→验收→修订”。说明为什么这样选择，并给一个不合适方案及其具体错误。

设计循序渐进练习：辨认边含义、补漏/纠错、从规格手画、做受约束修改。附答案或自检依据，但学习者可以先不看答案。工具无关：纸笔和常见矢量编辑器均可；自动化示例是可选路径。对新生首次使用的术语做短解释，不假设已掌握所有微架构名词。

【阶段 F：自己画、自己修改】
为三个原创示例分别提供目标问题、实体/边/不变量、布局计划、可编辑矢量源、SVG 和实际预览。选互补任务，例如架构总览、带反馈的机制流程、软硬件或模拟器边界；以仓库已实现示例为准，不谎称某示例属于真实论文。

先通过语义门槛，再检查实际渲染中的文本、线条、路径、裁切、图例及目标展示尺寸。记录每次改动的失败编码、位置、理由、前后版本、风险和复检。视觉检查工具不可用时标 not_run，不能用“SVG 可解析”冒充视觉已通过。改标签/增加模块等操作必须验证源可编辑，不仅输出截图。

发现关键语义错误就修复，不得用视觉评分抵消。没有实质失败时不伪造改进；若为教学故意植入错误，要注明练习性质。

【阶段 G：评估计划，不预写胜利】
在冻结归纳规则之后，按论文或规格来源分组留出任务。比较同模型/工具/预算下的直接生成与结构化流程；同时报告首版和修订后表现、调用/时间成本，避免给一组隐性额外预算。

关键语义错误是 hard fail。报告实体/关系/边界/时序错误、读者问题回答准确性与时间、目标尺寸可读性、规定修改任务的编辑时间和语义保持情况。编辑时间分离人工操作与生成等待。评审隐藏生成方法并随机顺序，记录评审背景与分歧。失败、超时、不可编辑输出也计入，不能只选好看的结果。未运行评估就明确写未运行；不声称有经验性提升。

【输出与完成条件】
先给有用结果，再给工作记录：
- 精确说明实际完成的论文/图/示例数与查看深度。
- 给出可以立即使用的选图方法、教学路径、可编辑图及其入口。
- 列出已证实观察、待验证模式、未检查项和阻碍。
- 提供文件路径、测试/渲染检查结果、修订日志与下一项最有价值的缺口。

本轮完成条件为 v0.1 的实际文件和核验闭环，而不是把整个未来研究做完。若流程暴露可恢复问题，修好并复检；权限或来源不可达则诚实报告，继续独立可做的工作。不要以需要用户样本为由停下。外部发布只在明确授权范围内进行，发布后核对实际远端状态，不能把本地保存说成已上传 GitHub。
```

## 如何手工使用这份 Prompt

不必一次做完所有阶段。新生先走阶段 B、C、E、F：选一个原创机制，用一页纸列问题和实体/边，画单色图，按清单修一次。研究阶段再逐步补上来源、模式与评估。编程生成只是同一方法的另一种执行方式，不是学习前提。
