# 图与图集验收清单

适用于纸笔草图、手工矢量图和自动生成图。自动检查只能覆盖部分项；`passed`、`failed`、`not_run`、`not_applicable` 必须区别记录。

## Gate 0：任务与证据

- [ ] 目标是解释结构/机制，而非实验结果图。
- [ ] 每张图有一句读者问题，图集覆盖必要贡献，没有为了凑模板而画的图。
- [ ] 真实论文观察有来源/图号/页码/查看深度；原创图明确标 synthetic。
- [ ] 官方投稿要求、社区中观察到的习惯、项目自定样式分别标记；没有把习惯称为强制规范。

## Gate 1：语义硬门槛

- [ ] 所有必要实体存在；没有未经规格支持的新实体。
- [ ] 每条边的端点、方向、类型、条件和标签正确。
- [ ] 数据流、控制流、包含关系、映射关系未混淆。
- [ ] 所有权/层级/软硬件/宿主目标等边界正确。
- [ ] 并发、先后、等待、循环、返回与终止没有被布局歪曲。
- [ ] 图与正文、图注及跨图命名一致。

任一关键语义项失败即不得验收；继续修正，或明确标为未完成。视觉分数不抵消语义错误。

## Gate 2：全局阅读

- [ ] 主阅读顺序可解释；没有主顺序的结构图也能清楚看出组织原则。
- [ ] 主要信息先被看见，辅助细节不压过贡献。
- [ ] 容器是语义边界还是视觉分组有说明。
- [ ] 连线不会误穿不相关节点，交叉点不会被误读为连接。
- [ ] 跨面板的对应对象能被找到，编号不冲突。
- [ ] 静态结构与动态事件未在没有说明时混用。

## Gate 3：局部可读性与可访问性

- [ ] 在实际计划的单栏/双栏展示尺寸查看，而非只放大检查。
- [ ] 文字无裁切、重叠、溢出；标签能唯一对应实体或边。
- [ ] 箭头头部可见，线宽/线型足以区分；缩写有解释。
- [ ] 相同视觉编码含义一致；颜色之外仍有文字/形状/线型等线索。
- [ ] 黑白或低色辨情况下仍能读懂主要关系。
- [ ] 图例仅解释真实使用的编码；配色不是无意义装饰。
- [ ] 大小/面积/距离若不是定量含义，不会诱导不正确推断。

尺寸、字体和导出约束应查当前投稿指南；这里不虚构所有会议统一的字号规范。

## Gate 4：可编辑与可复现

- [ ] 保存可编辑矢量源，文字和基本图形可操作，不仅是嵌入位图的 SVG。
- [ ] 源、输入规格、导出图可对应；记录生成/导出方式及依赖。
- [ ] 做一次真实编辑：改标签或增删节点，然后导出并复检相关关系。
- [ ] SVG/其他矢量文件可打开；实际渲染预览经过人工或图像查看检查。
- [ ] 发布不包含未获许可的第三方原图/PDF、秘密或个人数据。

## 自画自改协议

1. 先写语义清单，再画初版；保存 `v1`，不要只保留最终图。
2. 看实际渲染，定位一个明确失败，标注失败编码和位置。
3. 选择最小修复：例如移标签、增走线区、拆面板，而不是无理由全图重做。
4. 保存 `v2`，检查修复目标及其邻近元素，同时重跑语义门槛。
5. 如果没有实质失败，记录“检查后未发现需改项”，不要伪造修订；若作为修订练习，可预先设计故障并明确这是练习。
6. 完成条件是必要问题可回答、语义正确、目标尺寸可读、源可编辑；不是“看上去更像论文”。

修订日志模板：

| 版本 | 检查方式/尺寸 | 发现与位置 | 编码 | 改动 | 语义回归检查 | 结论 |
|---|---|---|---|---|---|---|
| v1→v2 | 实际预览 | 如返回标签盖住箭头 | L2/V1 | 将标签移至独立走线区 | 返回边端点/方向不变 | passed / failed |

## 教学验收

让学习者不用看答案完成三件事：指出每种边的含义；沿一次具体操作解释图；说明为什么选择这个图型而非另一个图型。再给一个修改要求，观察能否保持语义。答不出来时先检查标注和教学说明，不把问题一概归咎于新手。
