# 图形模式登记册：实例观察与待验证假设

本页区分**有原图依据的局部观察**与**待验证的设计假设**。当前不给出出现频率、会议偏好或“最佳实践已被证实”的结论。原创示例能证明模式可操作，不能证明真实论文普遍如此。

先读 [真实研究图的跨论文对照](../corpus/expert-comparisons.md) 理解取舍，再读 [研究综合审阅](../corpus/synthesis-review.md)。代码示例不是成熟图的审美上限：重点是判断哪些细节构成论证证据、哪些可以省略，以及何时必须换一种图法。

## 模式卡的必填项

`id / 名称 / 状态 / 读者问题 / 主对象 / 适用条件 / 语义不变量 / 全局布局 / 局部编码 / 不适用情况 / 真实证据ID / 反例ID / 原创示例ID / 已知失败 / 修订版本`。

状态流转：`hypothesis`（提出）→ `observed`（有可核验原图实例）→ `pilot-supported`（多个独立实例且明确检查反例）→ `evaluated`（留出任务评估）。状态提升必须附证据；不设一个样本数门槛就自动称普遍规律。本轮部分卡提升至 `observed`，仅表示存在符合该局部组织方式的已检查实例，不表示整张模式卡的所有建议都已验证。任何卡均未达到 `pilot-supported` 或 `evaluated`。

## P01：总览锚点 + 局部放大

- **状态：observed（局部组织方式）**。证据：`eyeriss-isca2016 / Fig.1`、`rowclone-micro2013 / Fig.1`（[专家记录](../corpus/expert-papers.json)），以及 `aifm-osdi2020-f5`（[基础记录](../corpus/figures.json)）。[Eyeriss 原图 p.2](https://d1qx31qr3h6wln.cloudfront.net/publications/ISCA_2016_Eyeriss.pdf#page=2)与 [RowClone 原图 p.2](https://www.pdl.cmu.edu/PDL-FTP/NVM/rowclone_micro13.pdf#page=2)均有带关联的下钻；不是“每张总览必须配放大图”的证据。

- **问题**：新机制在哪里，细节如何实现？
- **适用**：全系统边界与局部机制同时重要，单图信息负荷过高。
- **语义不变量**：细节图的端口/模块必须能映射回总览；放大不能暗中改变连接。
- **全局布局**：总览保持少量主要关系，局部细节独立面板；用同名标签或显式索引连接。
- **局部编码**：贡献区域用一致边框/填充强调；背景组件降强调但不消失。
- **反例/风险**：细节本身已足够解释贡献时，重复总览增加翻找；放大连接线可能被误读为数据流。

## P02：主路径 + 独立回路通道

- **状态：hypothesis**。`firesim-isca2018-f3` 和 `plasticine-isca2017 / Fig.3` 提供数据与控制空间组织的邻近观察，但尚不足以证明本卡“主路径 + 独立反馈回路”的完整组合。原创流程图仅用作可操作性例子。

- **问题**：请求往哪里走，反馈怎样返回？
- **适用**：主数据路径明确，少量反馈/控制边容易横穿主路径。
- **语义不变量**：返回边不能为了简化而删掉；控制与数据不同义。
- **全局布局**：沿一个方向排列主路径，将反馈安排到独立走线区；不强行拉直真实循环。
- **局部编码**：边类型用标签及线型辅助区分，不能只靠颜色。
- **反例/风险**：高度对称网络没有唯一主路径；强行线性排列可能制造不存在的先后关系。

## P03：共享骨架的机制对照

- **状态：observed（共同参照上的路径/关系比较）**。证据：`rowclone-micro2013 / Fig.5` 在同底图对照 TRANSFER 与 READ/WRITE；`eyeriss-isca2016 / Fig.6` 在相同网格三面板分别展示数据关系，后者不是 baseline/proposal 对照。见 [RowClone p.5](https://www.pdl.cmu.edu/PDL-FTP/NVM/rowclone_micro13.pdf#page=5)、[Eyeriss p.7](https://d1qx31qr3h6wln.cloudfront.net/publications/ISCA_2016_Eyeriss.pdf#page=7)。证据支持“共享参照”，不支持强制左右前后排法。

- **问题**：新机制相对旧机制改了哪一步？
- **适用**：贡献是局部结构/规则改变，基线语义可以准确说明。
- **语义不变量**：两侧共同部分使用相同命名；不同部分必须确有依据；不借机暗示性能收益。
- **全局布局**：同尺度、同阅读方向、对应位置对齐。
- **局部编码**：单一强调色或边框标改变点，旧机制不故意画得混乱。
- **反例/风险**：设计范式不同没有可对齐实体时，强行一一对应会误导。

## P04：边界分组 + 接口契约

- **状态：observed（边界与执行/职责位置；完整接口契约仍需逐例核对）**。证据：`firesim-isca2018-f1`/`firesim-isca2018-f2` 分开目标拓扑与宿主映射；`aifm-osdi2020-f3` 区分本地/远端与 API 层次。见 [FireSim p.3](https://sagark.org/assets/pubs/firesim-isca2018.pdf#page=3)、[AIFM p.4](https://www.usenix.org/system/files/osdi20-ruan.pdf#page=4)。颜色归属和位置可表达不同维度，不能把所有嵌套框都解释为物理包含。

- **问题**：软件/硬件或宿主/目标各自做什么？
- **适用**：跨层职责、隔离或接口是贡献核心；特别关注 Co-design 与 Simulator。
- **语义不变量**：包含不等于部署；跨界关系需标对象和方向。
- **全局布局**：先画边界再安排内部实体，跨界端口集中且可追踪。
- **局部编码**：容器标签明确边界性质，不用“虚线框”暗示未说明的语义。
- **反例/风险**：多个相交边界无法用简单嵌套表达，需面板或独立映射而非误置容器。

## P05：静态组织与动态执行分图

- **状态：observed（图集中的职责分工）**。证据：`eyeriss-isca2016 / Fig.1, Fig.5, Fig.6` 分别提供层级背景、原语时间展开与逻辑数据流；`rowclone-micro2013 / Fig.1, Fig.4` 分别给层次和状态转换。见 [Eyeriss p.6](https://d1qx31qr3h6wln.cloudfront.net/publications/ISCA_2016_Eyeriss.pdf#page=6)、[RowClone p.4](https://www.pdl.cmu.edu/PDL-FTP/NVM/rowclone_micro13.pdf#page=4)。这是可见分工的观察，并未访谈作者确认拆图动机；不推导“必须先总览后细节”。

- **问题**：模块之间是什么关系，与一次操作发生了什么有何区别？
- **适用**：静态连接无法表达等待、并发、重试或状态转换。
- **语义不变量**：动态图不增加静态图没有依据的参与者；时间顺序明确。
- **全局布局**：结构图按层级组织，过程图按事件或状态组织，跨图统一名称。
- **局部编码**：步骤编号仅用于次序，不拿实体 ID 冒充时间。
- **反例/风险**：过程只有两三个显然的步骤时，分图可能只是重复。

## P06：示意规模与省略项作为技术声明

- **状态：observed（图注明确声明）**。`plasticine-isca2017 / Fig.3` 注明仅展示 4 stage、4 lane 并省略部分控制信号；`Fig.5` 说明真实规模为 16×8。来源：[Plasticine p.5](https://csl.stanford.edu/~christos/publications/2017.plasticine.isca.pdf#page=5)，记录见 [expert-papers.json](../corpus/expert-papers.json)。
- **问题**：看到四个重复框，读者可否推断真实设计只有四个？
- **语义不变量**：示意规模与技术规格不同；省略不能删除证明机制所需的条件。
- **全局布局**：压缩重复结构，保留足以读出重复规律与接口的局部展开。
- **局部编码**：倍数、索引、省略号与图注共同说明范围；只在已核实后写实际数量。
- **不适用/风险**：若准确实例数本身就是当前要解释的关系，应完整给出数量信息；不能以“示意”掩盖错误拓扑。

## 证据边界与当前状态汇总

| 状态 | 模式 | 当前可说什么 |
|---|---|---|
| observed | P01、P03、P04、P05、P06 | 指定论文的指定图中观察到相应局部组织或明确声明 |
| hypothesis | P02 | 有邻近观察，完整组合及适用范围尚待核验 |
| pilot-supported / evaluated | 无 | 尚无试点稳定性或留出效果证据 |

本轮合并记录为 **6 篇、18 幅非实验结果图**：基础集 3 篇 9 图与专家对照集 3 篇 9 图，来源文件各自保留。基础集按 `figure.id` 定位，专家集按 `paper.id + figure.number` 定位；不要把临时组合引用误认成现有 JSON 字段。两组核验记录均声明实际查看原 PDF 渲染、图注及相邻正文；本页是对这些可追溯标注的综合，不另行声称本页编辑者独立复看了全部原图。

样本有目的选择且集中于 ISCA/MICRO/OSDI，尚未覆盖全部 8 个会议，也不是完整 CPU/cache/coherence 图谱。不同作者团队不是独立随机抽样，更不能以机构名气验证设计原则。所有“应当怎样改”的句子是项目判断，非作者意图；反例和学习用效果仍待继续检验。

## 如何用论文修正候选

对每个真实实例问：图真的解决了该问题吗？其布局是否由别的因素决定？有没有同类问题却采用相反布局的实例？记录原图证据，不把自己的重绘算原图。模式可以合并、缩小适用范围或删除；优先保留“何时不该这样画”的信息。

## 人工与 AI 共用的使用方式

人工绘图者按“问题→适用条件→不变量→草图”选模式；AI 按同样顺序输出结构化计划。两者均须经过 [质量检查](quality-checklist.md)，不能以套上模板作为完成标志。风格规范另见 [风格与约定](style-and-conventions.md)，模式不决定字体或配色品牌。
