# 标注指南 v0.1

## 1. 证据等级与记录单位

每条记录拥有稳定的 `paper_id`、`figure_id`（含子图）、`annotation_version`、`annotator` 和 `review_status`。记录官方/作者来源 URL、获取日期、论文页码及图号，引用短摘录时注明位置。分别记录 `metadata_verified`、`text_inspected`、`figure_inspected`；没有实际看见图就不得标注颜色、位置、箭头或视觉风格。`unknown` 与 `not_applicable` 分开；不能用猜测填空。

观察字段只写图上能看到或正文明确解释的内容；推断字段写理由与置信度；建议字段写拟改动。不得将建议回填为原图事实。

## 2. 论文层字段

- 问题、对象、约束、贡献列表（每条附摘要/正文位置）。
- 目标读者的已有知识；看图后应能回答的问题。
- 现有图集与每张图的论证职责；缺图、多图、图与正文重复的判断及依据。
- 贡献 → 问题 → 图的覆盖矩阵；没有图也能清楚说明的贡献允许标记“文字足够”。
- 原论文的取舍不自动等于最优方案；重画建议单列。

## 3. 主对象分类：可多标签，但必须有主类

| 主类 | 判据 | 典型语义关注点 |
|---|---|---|
| System | 多组件协作提供运行时服务 | 边界、部署、请求/响应、状态归属 |
| Architecture / Microarchitecture | 硬件组织或处理单元内部设计 | 资源、数据通路、控制通路、层级 |
| Mechanism / Protocol | 关键贡献是动作规则或交互过程 | 状态转换、条件、因果、事件顺序 |
| Compiler / Toolchain | 程序转换或分析工具链 | 表示形式、pass、输入输出、反馈 |
| Simulator | 建模、执行或评估被模拟对象的模拟器 | 宿主与目标、模型与执行引擎、时间推进、接口、验证边界 |
| Data structure / Mapping | 数据表示、分区、布局或映射 | 索引、位置、所有权、映射方向 |
| Co-design | 贡献依赖软硬件跨层协作 | 两侧职责、接口、可见状态、同步 |

Simulator 必须独立可检索：模拟器自身架构、被模拟机器架构、仿真工作流不得混为一张没有边界的图。一个系统使用模拟器做评测，不代表其主对象就是 Simulator。

## 4. 单图语义字段（先填此节）

- **任务**：总览 / 结构 / 流程 / 时序 / 状态 / 数据布局 / 映射 / 机制对照，可多选，指定主任务。
- **实体**：稳定 ID、标签、实体类型、所属层/容器、是否贡献相关、是否可以省略。
- **关系**：源、目标、类型、方向、标签、触发条件；双向通信应明确是两条有向关系还是一种对称关系。
- **包含**：真实的部件关系还是仅视觉分组；嵌套的语义必须写明。
- **时间/状态**：有无全局时间轴，步骤顺序、并发/互斥条件、循环和终止条件。
- **边界**：软件/硬件、节点/网络、信任域、宿主/模拟目标、离线/在线等。
- **不变量**：不能删除/反向/合并的边、不能错放的实体、必须保留的状态。
- **文字支撑**：语义依据来自图例、图注或正文哪一处；冲突先登记，不自行修正原论文。

## 5. 全局布局字段

记录主阅读方向、入口/出口、层级、面板顺序、分组原则、对齐骨架、大小表达的含义、跨组边、回路通道、连接交叉与留白。注明某一空间位置是否有语义（地址顺序/时间/层级），还是纯排版。

允许“未发现单一阅读方向”；不要为了套模板伪造主流程。结构图不一定是流程图，空间相邻不自动表示依赖。

## 6. 局部视觉字段

字体及字号层级、文字密度、形状及语义、填充/边框、线宽/线型、箭头头型、颜色角色、图例、缩写、图标、编号、标签贴附方式。记录同色是否同义、不同线型是否有图例；仅“蓝色矩形”不是有用规则，要说明它承担什么编码。

如原图没有可量测尺寸，记录相对层级，不臆测精确 pt 值。布局与局部视觉分开，不能以一个“风格”字段混合概括。

## 7. 失败分类与修订记录

| 编码 | 失败 | 例子 | 优先级 |
|---|---|---|---|
| S1 | 实体/关系增删 | 为了整齐删去必要返回通道 | 阻断 |
| S2 | 方向/类型错误 | 将控制边画成数据边 | 阻断 |
| S3 | 边界/所有权错误 | 把宿主线程置于模拟核心内部 | 阻断 |
| S4 | 时间/因果错误 | 将并行步骤画成必然串行 | 阻断 |
| N1 | 论证遗漏 | 图集未解释核心贡献如何发生 | 阻断或需明确降级范围 |
| L1 | 阅读顺序不明 | 多入口没有编号/主次 | 待修 |
| L2 | 连线歧义 | 标签跨线、箭头端点不确定 | 待修；影响语义则升为 S 类 |
| V1 | 文本/元素不可读 | 裁切、重叠、目标尺寸太小 | 待修 |
| V2 | 编码不一致 | 同色代表不同角色且无说明 | 待修 |
| E1 | 不可编辑/不可复现 | 只有截图、源文件缺失 | 阻断交付 |
| P1 | 证据/许可错误 | 未看图却声称视觉规律 | 阻断发布 |

每次修订记录：版本、失败编码、可定位的证据、最小改动、预期收益、可能回归、复检结果。禁止“整体更高级”作为修订理由。

## 8. 复核与分歧

试点阶段同一份规格先独立标注，再比较主对象、实体/边、不变量及读者问题；必要时同一人隔轮复标也可，但必须标明不是独立双人评审。优先解决语义分歧，然后讨论布局。保留原始标签、裁决依据和规则版本，不覆盖争议历史。以逐字段一致情况报告可复现性，不能只报一个没有定义的总分。
