# 项目计划：从论文贡献到可编辑的架构图

## 要解决的问题

本项目不收集实验结果图，也不以“美观”代替正确。目标是回答三个可以检验的问题：

1. **应该画哪些图？** 从论文贡献、读者疑问和已有文字出发，选择最小且充分的图集合。
2. **每张图如何组织？** 先确定实体、关系、边界、状态和时间，再确定全局布局及局部视觉编码。
3. **怎样自己画、自己改？** 生成可编辑矢量源，用语义核对、渲染检查及定向修改形成闭环，保留失败和修订证据。

## 面向新生的学习轨道

项目同时服务人的理解与 AI 执行，不能只交付提示词。人工轨道用纸笔或任意可编辑矢量工具完成“读图—选图—草图—修改”；自动轨道执行同一语义与验收协议。学习入口为 [学习路径](learning-path.md)、[风格与约定](style-and-conventions.md) 和 [练习](exercises.md)。必须区分带来源的当年官方要求、非强制的观察习惯以及本项目默认样式；不声称存在所有会议统一的配色或字号规范。

研究对象覆盖 OSDI、ISCA、MICRO、DAC、HPCA、ASPLOS、ATC、IPDPS 的系统、体系结构、软硬件协同及模拟器论文中的解释性图。会议是采样分层，不是审美标签；不能把单篇论文的画法归纳为整个会议的风格。ATC 的历史名称与具体年份名称应分别记录，检索注意 USENIX ATC 与 2026 年 ACM SIGOPS ATC 的命名衔接；每条记录以其正式来源为准。2026 年名称及转为 ACM 会议的依据见 [ATC 2026 官方 CFP](https://atc.sigops.org/2026/cfp.html)（核验：2026-11-01）。

## 边界

**纳入**：系统总览、模块架构、微架构、数据流、控制流、机制流程、协议/时序、数据结构与布局、映射、软硬件接口、模拟器结构、动机中的机制性示意。

**排除**：吞吐/延迟/能耗等实验结果曲线、柱状图、散点图、统计表及纯评测比较。混合图只标注可独立理解的机制子图，记录排除区域；不把结果子图带入生成目标。图中数值若用于解释地址位段、缓冲容量或步骤编号，不因此自动排除。

不承诺某个生成器优于人工或直接提示；不把当前候选模式当成已证实共性；不公开上传第三方论文 PDF 或原图，除非许可明确允许。

## 研究单位与双层模型

- **论文层**：贡献 → 读者必须回答的问题 → 必要图集 → 图与正文的分工。
- **单图语义层**：实体、类型、关系、方向、包含、状态、事件、读者阅读任务。
- **全局布局层**：阅读方向、层级分组、主次、对齐、跨层连接、面板顺序、留白分配。
- **局部视觉层**：字体、形状、边框、线型、箭头、填充、颜色、编号、图例、标签位置。

局部视觉和全局布局必须分开标注、分开消融；漂亮的局部组件不能补救错误的全局阅读顺序。

## 当前里程碑与完成证据

| 阶段 | 规模与产出 | 完成条件 |
|---|---|---|
| v0.1 启动 | 初始目标 3–4 篇真实种子记录（当前记录已扩至 6 篇 18 图）、3 个原创合成示例、可运行的源到矢量输出流程、本套协议 | 实际文件和测试可复核；真实记录注明访问/标注深度；合成示例不冒充论文证据 |
| 小规模试点 | 扩展到 12–20 篇，尽量覆盖 8 个会议及主要对象类型 | 能复现标注；争议有裁决；至少识别适用条件和反例，而不只是列图形元素 |
| 条件性扩展 | 试点证明方法可用后，考虑约 100 篇 | 先修正重复模式、来源不足和分类不稳定的问题；报告覆盖偏差，不以数量代替质量 |
| 评估 | 冻结模式和规则后，对留出的规格执行比较 | 公开规格、运行配置、原始错误、修订及计时方法；允许负结果 |

上表除明确写出的当前记录数外均为计划，不是已完成计数。当前基础集 `corpus/papers.json` / `figures.json` 为 3 篇 9 图；专家集 `corpus/expert-papers.json` 为另外 3 篇 9 图，合计 6 篇 18 图，均有原图查看记录。这个数不代表所有论文完整图集已标注或 8 个会议已覆盖。优先读 [跨论文研究判断](../corpus/expert-comparisons.md) 与 [综合审阅](../corpus/synthesis-review.md)：当前学习重心是成熟研究者的抽象、省略、对比基准及论证取舍，而非代码演示。精确状态以仓库实际 corpus、examples、测试输出和提交记录为准。启动不依赖用户先提供论文或手画样例：原创规格可作为流程验收输入，但不能作为顶会经验的证据。

## 工作流与交付合同

1. **取样与来源核验**：选论文，记录正式链接、年份、会议正式名、图号、页码及查看深度。看不到全文时仅做候选登记，不做图像视觉断言。
2. **论文层问题分解**：写出贡献原文位置/释义、读者问题、候选图集合以及每张图的必要性。
3. **双层标注**：按 annotation-guide 先语义后布局/视觉；事实与解释分栏。
4. **归纳候选模式**：每个模式写触发条件、适用范围、反例、证据 ID 和未知项；跨论文验证后再升级状态。
5. **生成与修订**：规格 → 语义校验 → 布局计划 → 可编辑源 → SVG → 实际渲染检查 → 定向改动 → 再校验。保留前后版本。
6. **评估与发布**：冻结训练/归纳集及留出集，运行基线和结构化流程；仅发布有权发布的素材与可复现记录。

每张原创图至少交付：输入规格、可编辑源、SVG、预览、语义清单、质量检查结果和修订日志。若某种预览工具不可用，要明确写“未渲染检查”，不能以 XML 可解析代替视觉合格。

## 评估设计（计划，尚非结果）

**比较组**：A 为同一模型直接根据文字生成图；B 为贡献/读者问题 → 必要图集 → 语义规格 → 布局 → 渲染/修订的结构化流程。固定任务、模型版本、可用工具、输出格式、时间/调用预算和停止规则；同时报告首版与最终版，避免把 B 的额外修订预算隐藏起来。

**留出原则**：按论文/规格来源分组留出，不把同一论文的改写规格分到两组；模式归纳不可看到留出答案。原创合成规格只测试工具链，不等价于真实论文泛化。

**主要指标**：实体遗漏/新增、边类型或方向错误、边界错误、时序错误、贡献表达缺失；任一关键语义错误即语义验收失败，不得用美观分数抵消。

**次要指标**：读者问题回答正确率和用时、可辨识的阅读顺序、标签/路径歧义、目标尺寸可读性、规定编辑任务的有效编辑时间及修改后语义保持率。编辑任务例如新增一个模块、交换两个阶段、增加返回通道；统一任务说明、起止点、工具和操作者经验，分别记录人工操作时间与生成等待时间。

盲评时隐藏生成方法并随机顺序；记录评审者背景、分歧及裁决。小样本先报告逐例结果和不确定性，不宣称统计显著改善。将中途失败、超时和无法编辑的输出保留在分母。

## 近期优先级

1. 先用真实论文对照练习抽象、省略和选择图型的判断；原创示例用于降低复杂度、验证理解，不作为终点。
2. 复核六篇十八图的证据边界，补齐论文层问题，并让原创示例达到语义正确、渲染可读和有据修订；不急于扩大数目。
3. 用同一协议重复标注一个样例，定位模糊字段，更新版本。
4. 再扩充缺失的会议/对象/图类型；尤其检查 Simulator 是否被错误并入普通 System。
5. 达到试点完成条件后才冻结候选规则并进行留出评估。
